# تحقق الدفعة الثانية — مطابقة سجلات المصدر

2026-10-07 (بغداد). نجحت مجموعة Laravel كاملة: 103 اختبارات و929 تأكيداً على SQLite، تشمل 7 اختبارات جديدة و99 تأكيداً للمطابقة التفصيلية. نجحت مجموعة Playwright كاملة: 22 سيناريو على Chromium، مع API محاكاة لاختبارات الواجهة. نجح بناء Vite للإنتاج وPint للملفات المعدلة. بعد إضافة تسمية الوصول لحقل الملف والتحقق من صحة الرفع في منع التكرار أعيدت اختبارات المطابقة السبعة وسيناريو الرفع وبناء الواجهة ونجحت.

التغطية: كشف معرفات مختلفة رغم تطابق المجاميع؛ مقارنة تاريخ وعملة سجل خرج من النطاق؛ كشف اختلاف الفاتورة المرتبطة ومبلغ الحركة؛ ملفات XLSX فعلية وقيم USD/IQD الدقيقة؛ التحصيل بعد نهاية فترة الفواتير حتى as_of؛ حفظ الأصفار في المعرف؛ تشفير الأدلة وعدم إرجاع كل السجلات بحمولة التفاصيل؛ إعادة إرسال نفس الملف دون تكرار ورفض الملف المختلف بنفس المفتاح؛ stale بعد تغيّر مبلغ أو رمز عميل مع حفظ الأدلة الأصلية؛ رفض المعرفات المكررة والدقة الخاطئة والعملة والفترة والحركات غير المطابقة لنطاق المصدر؛ الصلاحيات وعزل الشركات والتصفية والترقيم؛ رفع multipart مع مفتاح منع التكرار وتأكيد المستخدم وعرض فروقات الحقول.

تمت معاينة شاشة التفاصيل مع بيانات واجهة محاكاة. لم تُجرَ اتصالات حية مع نظام ERP أو مزود AI، ولا تجربة بيانات شركة أو MySQL/Redis أو نشر إنتاجي. التقرير المرفوع لا يثبت تغطية كل البرنامج؛ لا تغير financial records أو قواعد المكافآت أو coverage_confirmed. أرقام المجاميع تتبع النطاق الطبيعي، والفحص التفصيلي يضيف معرّفات المصدر لتحديد تغيّر النطاق. الملف الأصلي لا يُحفظ؛ السجلات المعيارية والبصمة محفوظة مشفرة.
