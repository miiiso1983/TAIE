# مراجعة التوقع الأسبوعية المجدولة

الجداول تحدد منتجاً ومنطقة ومصدراً و12–104 أسابيع تاريخية وساعة تجهيز يوم الاثنين بتوقيت الشركة. عند الإنشاء تُعرض أحدث فترة مكتملة للمراجعة. كل موعد لاحق يجهز فترة جديدة ويرفع رقم النسخة؛ لا يُنسخ إقرار التغطية السابق ولا يُولد توقع دون مراجعة بشرية لهذه الفترة. التوقع الناتج للأفق الثاني، أي أسبوع بعد مهلة أسبوع، ليتيح الحفظ قبل بداية أسبوع التوقع.

الأذونات المطلوبة: advisor.forecast.manage وadvisor.forecast.run وadvisor.sales.read وdata.sensitive.read وadvisor.data.review. يعاد فحص عضوية مالك الجدول وحالته وصلاحياته والاشتراك عند مهمة التجهيز وعند المراجعة. تُوقف المهمة الجدول عند فقدان الحق، ولا تطبع أخطاء مزود أو أسرار. لا رسائل خارجية، ولا اتصالات AI/ERP.

المسارات: GET/POST `/advisor/forecast-schedules`، POST `/{uuid}/review` و`/{uuid}/disable`. mutations تتطلب مفتاح idempotency؛ المراجعة والإيقاف يتطلبان نسخة الحالة. المراجعة القديمة أو الفترة التي تجاوزها الأسبوع الحالي تُرفض. لا توليد جزئي عند نقص سطور الفواتير؛ المعاملة تتراجع كاملة ويبقى طلب المراجعة. الجداول المكررة النشطة لنفس المنتج/المنطقة/المصدر ممنوعة؛ إيقافها يبقي الأرشيف.

تحتاج ترحيل advisor_forecast_schedules وترقية كتالوج الصلاحيات ومنحها صراحة، وإعداد scheduler/worker للطابور analytics. لا تنفذ شاشة الإعداد ذلك. تحديث الجاهزية يفحص المخطط والصلاحية الجديدة. لم تُطبق ترحيلات أو مزامنة أدوار على قاعدة الجهاز.

اختبارات: جدولة بتواريخ ثابتة، ضرورة مراجعة كل نطاق، منع تكرار المهمة، عدم توليد آلي، توقيت أسبوع المستقبل، توقف عند سحب الحق، تعارض النسخة والعزل والصلاحيات، مع جميع اختبارات النظام: 151 اختباراً / 1569 تأكيداً. بناء الواجهة ناجح؛ تشغيل scheduler/worker الحقيقي في بيئة إنتاجية لم يُقبل بعد.
