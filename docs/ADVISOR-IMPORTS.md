# استيراد بيانات المستشار — الدفعة الأولى

التنفيذ الحالي يدعم CSV وXLSX وربط الأعمدة ضمن المرحلة 1 من ADVISOR-ROADMAP.md. أُضيفت مؤشرات مبيعات وتحصيل أولية في ADVISOR-METRICS.md، وأُضيف محرك مراجعة حتمي للمكافآت في ADVISOR-BONUS.md. لا توجد توصيات نموذج AI في هذا المسار.

## الاستخدام

بعد الترقية شغّل migrate وdb:seed وteami:permissions:sync-owners دون تغيير مفاتيح التطبيق. من قائمة الحساب اختر **بيانات الشركة**. يحتاج المستخدم data.import.manage وdata.sensitive.read، وإضافة إلى ذلك hr.employee.create للموظفين أو sales.customer.create للعملاء أو data.sales.import للفواتير والتحصيلات والمرتجعات، وsales.target.write للأهداف، وhr.compensation.write للتعويضات السنوية. لا تمنح هذه الصلاحيات لجميع الموظفين تلقائياً؛ المالك الحالي يختار مسؤول بيانات موثوقاً.

اختر النوع، نزّل القالب، أضف سجلاتك، وارفع CSV UTF-8 أو XLSX. اضغط «فحص الأعمدة وربطها»، واختر الورقة ثم اربط أعمدة المصدر بالحقول المطلوبة. الأعمدة الإضافية تُتجاهل والحقول الاختيارية يمكن تركها فارغة. القالب الأصلي CSV يمكن معاينته مباشرة. رمز المصدر ثابت لكل نظام؛ الافتراضي primary. استورد الموظفين والعملاء أولاً ثم الفواتير ثم التحصيلات. المعاينة لا تضيف أي سجل إلى الأعمال. صحّح الأخطاء وأعد الرفع، ثم اعتمد الدفعة كاملة. وقت الاعتماد يعيد الخادم التحقق تحت قفل الشركة وفي معاملة واحدة؛ تكرار الاعتماد أو رفع الدفعة المعتمدة نفسها لا يضيف السجلات مجدداً. الاستيراد إضافة فقط، ولا يعدّل الموجود أو يحذفه. يدعم تاريخ YYYY-MM-DD والأرقام الغربية بفاصل عشري نقطة.

الحد: ملف 1MiB و1000 سجل. القالب يحدد حقول النظام؛ الربط يسمح بأسماء وترتيب مختلفين لأعمدة الشركة. رأس الورقة أول سجل غير فارغ، وأسماء أعمدته فريدة وغير فارغة. الحقول المطلوبة لكل نوع موضحة أدناه؛ الأعمدة الاختيارية تبقى موجودة في رأس الملف وتُترك قيمتها فارغة. الموظف المستورد لا يُنشأ له حساب دخول أو تعويض أو موافقة تلقائية.

| النوع | الأعمدة المطلوبة | الاختياري |
|---|---|---|
| employees | employee_number, first_name, last_name | work_email, hired_at |
| customers | customer_number, name | email |
| invoices | external_id, invoice_date, due_date, customer_number, employee_number, currency, net_amount | لا يوجد |
| receipts | external_id, invoice_external_id, receipt_date, currency, amount | لا يوجد |
| returns | external_id, invoice_external_id, return_date, currency, amount | لا يوجد |
| targets | external_id, employee_number, period_from, period_to, currency, amount | لا يوجد |
| compensation | employee_number, annual_base, currency, effective_from | effective_to |

المعرّفات حتى 100 محرف (رقم الموظف والعميل حتى 60)، تبدأ بحرف أو رقم وتتكون من حروف/أرقام أو . _ / -. استخدم معرّفات ثابتة من المصدر. net_amount هو إجمالي الفاتورة المستوردة الذي تُطابق به التحصيلات، دون إعادة احتساب ضرائب أو خصومات؛ مسؤول البيانات يحدد قيمة المصدر الصحيحة. لا يُستنتج منه ربح أو استحقاق مكافأة.

USD: حتى منزلتين، مثلاً 10.25؛ IQD: حتى ثلاث، مثلاً 15000.000. لا فواصل آلاف أو رموز عملة، والمبلغ موجب. لا تحويل عملات؛ كل تحصيل يطابق عملة الفاتورة. الفاتورة تشير لعميل وموظف موجودين داخل الشركة. التحصيل يشير لفاتورة موجودة من رمز المصدر نفسه؛ مجموع التحصيلات، بما فيها سجلات نفس الملف، لا يتجاوز الفاتورة. المرتجع مرتبط بفاتورة من نفس المصدر، بنفس العملة وتاريخ لا يسبق الفاتورة، ومجموع المرتجعات لا يتجاوز قيمة الفاتورة الأصلية. سقف التحصيل يبقى قيمة الفاتورة الأصلية للسماح بتحميل التحصيل التاريخي قبل المرتجع؛ الفائض بعد المرتجع يظهر رصيداً دائناً ولا يُسوى آلياً. الدفعات المقدمة والإشعارات العامة والافتتاحيات ورد الأموال غير مدعومة.

## الحفظ والأمان

كل جدول مرتبط بالشركة، وروابطه تستخدم مفاتيح مركبة tenant_id. محتوى المعاينة وأخطاءها مشفران باستخدام APP_KEY؛ لا يُرجع محتوى الملف من API، وتظهر أول 100 مشكلة فقط. تُمسح الحمولة بعد الاعتماد. المعاينة تنتهي بعد 7 أيام وتُمسح بواسطة مهمة الصيانة كل ساعة، لذا يجب تشغيل المجدول. metadata الدفعة وأرقام السجلات المالية تبقى كمصدر للمرحلة التحليلية، ولا تُرسل إلى AI هنا. ملف CSV الأصلي لا ينسخ إلى public أو إلى تخزين التطبيق.

## API

كل المسارات تحت /api/advisor/imports وتتطلب المصادقة ونطاق الشركة وصلاحيات الاستيراد والبيانات الحساسة.

- GET /schemas: الأنواع والأعمدة التي يسمح الحساب باستيرادها.
- GET /: سجل دفعات مرقم؛ data يحتوي paginator.
- POST /inspect: multipart مع kind وfile؛ يعيد أسماء الأوراق والأعمدة دون بيانات الصفوف أو حفظ الملف.
- POST /preview: multipart form مع kind, source_system, file، وsheet (رقم الورقة من inspect، يبدأ بصفر) وmapping (JSON من حقول النظام إلى أسماء أعمدة المصدر). كل حقل مذكور في القالب يجب أن يكون مفتاحاً في mapping؛ الاختياري يقبل قيمة فارغة، والمطلوب يحتاج عموداً حقيقياً. data يحتوي UUID والحالة وعدد السجلات والأخطاء. هذا المسار يزيل التكرار ببصمة المحتوى، ولا يحتاج Idempotency-Key.
- POST /{uuid}/commit: طلب JSON مع Idempotency-Key مستحسن. اعتماد صريح، مع إعادة التحقق من صلاحيات النوع والاشتراك والصلاحية الزمنية والمراجع والتكرار.

التغيير في البيانات بين المعاينة والاعتماد يعيد 409 ويطلب رفع الملف مجدداً. ملف صحيح شكلياً لكنه يحتوي أخطاء صفوف يرجع 200 مع status=invalid، ولا يمكن اعتماده. ملف ذو رأس خاطئ أو فارغ أو يتجاوز الحدود يرجع 422. دفعة تخص شركة أخرى ترجع 404. الاشتراك المنتهي يحجب كتابة الاستيراد ويترك سجل القراءة متاحاً.

## القادم

الاستيراد الكبير في الخلفية، تصحيح الدفعات وإلغاؤها بإجراءات تعويض موثقة، وتأكيد تغطية المصدر والمصالحة والحضور والسياسات المتقدمة والمستشار اللغوي. بيانات التحليل لا تُعتبر دفتر حسابات قانونياً؛ لا يوجد نشر توصيات أو صرف أموال في هذه الدفعة.

## قيود Excel

قراءة XLSX عبر OpenSpout 4.32.0. ثبّت Composer dependencies المحددة وامتدادات zip وxmlreader وdom؛ bcmath مطلوب للمؤشرات المالية. XLS/XLSM وPDF وملفات كلمات المرور غير مدعومة. لا تُنفذ صيغ: يُرفض الملف ذو الصيغ أو الروابط الخارجية أو الماكرو/المكونات المضمّنة أو تصريحات XML. حوّل الصيغ إلى قيم واحذف الروابط الخارجية أولاً. التاريخ المخزن كنوع Date في Excel يتحول إلى YYYY-MM-DD؛ التاريخ كنص يجب أن يكون بهذه الصيغة. لا نُخمن أن كل رقم هو تاريخ. خزّن معرّفات فيها أصفار بادئة كنص، لأن تنسيق عرض Excel لا يمثل قيمة المعرف نفسها.

حدود XLSX: 10 أوراق، 100 عمود لكل رأس، 200 مكوّن للأرشيف، 20MiB إجمالي بعد الفك و10MiB للمكوّن الواحد، مع رفض نسب ضغط عالية في المكوّنات الكبيرة. تُفحص البنية قبل القراءة؛ بيانات الصفوف لا تُرسل إلى AI.

## الأهداف والتعويضات

الهدف يربط الموظف والعملة بفترة كاملة؛ لا يقبل تداخل أهداف نفس الموظف والعملة، حتى لو اختلف نظام المصدر. التعويض السنوي يُحفظ مشفراً في HR، ويُرفض تداخل فترات الموظف حتى لو اختلفت العملة. effective_to الفارغ يعني فترة مفتوحة. لا يغلق الاستيراد تعويضاً سابقاً ولا يعدّله؛ استخدم مسار HR الصريح إذا احتجت إغلاقه. الحد لكل مبلغ 10^12 وحدة صغرى؛ سجلات التعويض اليدوي خارج دقة أو حدود المستشار تُعتبر غير صالحة لحساب سقف المكافأة. الموظف المستورد وحده لا يحصل على تعويض أو حساب دخول.

## قوالب تفاصيل الأعمال الجديدة

أضيفت products وareas وcustomer_locations وinvoice_lines عبر CSV/XLSX والبوابة الموحّدة. راجع DATA-QUALITY-FOUNDATION.md لترتيب الاستيراد، صلاحيات الكتالوج، دقة الكميات، المناطق المحفوظة للفواتير ومنع مضاعفة مبالغ المبيعات. القوالب القديمة لم تتغير.
