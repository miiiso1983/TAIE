# Teami — جودة البيانات ومطابقة سجلات المصدر

تحديث الدفعة الثانية: 2026-10-07 (بغداد). أُضيفت مطابقة السجلات بالتفصيل إلى مصالحة المجاميع وتجهيز المنتجات والمناطق. لا تمثل اكتمال توقعات المنتجات أو إثبات اكتمال بيانات الشركة.

## ترقية المشروع الموجود

بعد النسخ الاحتياطي ودمج الملفات مع الحفاظ على .env وstorage وقاعدة البيانات ومفاتيح التشفير:

```sh
composer install
npm ci
npm run build
php artisan optimize:clear
php artisan migrate --force
php artisan db:seed --class=DatabaseSeeder --force
php artisan teami:permissions:sync-owners
php artisan test
```

الترحيلان: 2026_10_07_000001_create_advisor_quality_foundation و2026_10_07_000002_add_reconciliation_method؛ الثاني يميز مطابقة السجلات عن المقارنات السابقة دون حذفها. لا تشغّل migrate:fresh أو key:generate على المشروع الموجود. الصلاحيتان الجديدتان data.catalog.import وadvisor.data.review؛ المزامنة تمنحهما للمالكين وفق الآلية الحالية. امنح بقية المستخدمين الصلاحيات المطلوبة بحسب مسؤولياتهم.

## ترتيب استقبال البيانات

من «بيانات الشركة» استخدم CSV أو XLSX وربط الأعمدة والمعاينة قبل الاعتماد:

1. الموظفون والعملاء، كما في القوالب السابقة.
2. المنتجات: product_code,name,base_unit. رمز المنتج موحد داخل الشركة ووحدته الأساسية ثابتة.
3. المناطق: area_code,province_name,city_name. البلد IQ، والأسماء والأكواد تعتمدها الشركة. هذه ليست قاعدة رسمية للحدود أو تعداد السكان، ويمكن تسجيل المدن ومناطق التغطية المستخدمة في عملك.
4. ربط العملاء: customer_number,area_code. العميل والمنطقة يجب أن يكونا موجودين بالشركة؛ إضافة فقط، ولا يستبدل موقعاً مسجلاً.
5. رؤوس الفواتير: القالب السابق دون تغيير. تُحفظ منطقة العميل الموجودة وقت الاستيراد في الفاتورة. ربط العميل لاحقاً لا ينسب موقعاً تاريخياً إلى الفواتير القديمة.
6. سطور الفواتير: external_id,invoice_external_id,product_code,quantity,net_amount. تستخدم نفس مصدر رأس الفاتورة، والكمية بوحدة المنتج الأساسية، حتى ثلاث منازل عشرية و999999999.999. لا تحويل وحدات تلقائي.
7. التحصيلات والمرتجعات والأهداف والتعويضات وفق القوالب السابقة.

صافي مبلغ السطر غير سالب، وبعملة الفاتورة ودقتها؛ يمكن أن يكون صفر للسطر المجاني. الكمية موجبة. وزّع خصومات ومبالغ رأس الفاتورة على السطور عند إعداد المصدر، بحيث يطابق مجموع السطور مبلغ الرأس. تُرفض دفعة تتجاوز مجموع الفاتورة، بينما النقص يظهر ضمن جاهزية البيانات لأن السطور قد تُستورد على دفعات.

الحد الحالي 1000 سجل و1MiB لكل دفعة. المعاينة لا تكتب سجلات أعمال، والاعتماد يعيد التحقق داخل قفل الشركة ومعاملة واحدة. إضافة سطور لا تعيد إضافة مبلغها إلى مؤشرات المبيعات؛ الحسابات المالية تبقى من رؤوس الفواتير. المنتجات والمناطق ورموز العملاء موحدة بالشركة، ومعرّفات السطور فريدة ضمن الشركة والمصدر.

صلاحيات الاستيراد: data.import.manage + data.sensitive.read دائماً، ومعهما data.catalog.import للمنتجات والمناطق؛ sales.customer.update لربط العميل؛ data.sales.import للسطور. بوابة التكامل الموحّدة تقبل الأنواع الجديدة عبر HEADERS نفسها وصلاحيات الاتصال، ولا يضيف ذلك موصلاً أصلياً لأي برنامج.

## المصالحة

افتح «تحليل الأداء» ثم «مصالحة البيانات مع المصدر». تحتاج قراءة advisor.sales.read وdata.sensitive.read، وإنشاء المقارنة يتطلب أيضاً advisor.data.review.

اختر مصدر فواتير موجوداً بشركتك، والعملة، والفترة وتاريخ القياس. أدخل أعداد الفواتير والتحصيلات والمرتجعات ومبالغها من تقرير مستقل للنظام المصدر، واكتب مرجع التقرير وملاحظة المراجعة والإقرار. هذه مقارنة مجاميع بمرجع نصي؛ استخدم «مطابقة السجلات» أدناه لرفع تقرير المصدر التفصيلي. لا تنسخ أرقام Teami لإثبات تطابق المصدر مع نفسه.

النطاق: فواتير المصدر والعملة التي يقع تاريخها بين from وto، ثم جميع التحصيلات والمرتجعات المرتبطة بتلك الفواتير حتى as_of، بما فيها الحركات اللاحقة لنهاية فترة الفواتير. لا تستخدم تقرير حركات الفترة لكل الفواتير؛ قد يشمل فواتير أقدم ويعطي فروقات غير قابلة للمقارنة. الفترة القصوى 367 يوماً، حتى 10000 فاتورة و50000 حركة لكل نوع في نطاق الفحص الحالي. صفر قيمة صريحة، ولا يعني غياب الملف أن قيمته صفر.

تُحفظ الأعداد والمبالغ المتوقعـة والمستوردـة والفروقات الدقيقة، مع مرجع التقرير وملاحظة مشفرين. الفروقات = المستورد − المصدر. تتطابق المجاميع فقط إذا تطابقت الأعداد والمبالغ لكل الأنواع الثلاثة. كل عملة مستقلة؛ لا تحويل سعر صرف.

عند فتح مقارنة محفوظة، يعيد النظام حساب بصمة سجلاتها المالية: إذا تغيرت، تظهر «تغيرت البيانات — أعد المصالحة». النتيجة القديمة تبقى محفوظة؛ لا يُعاد اعتمادها تلقائياً. سجل القائمة يعرض نتيجة وقت الحفظ، والحالة الحالية تُفحص عند فتح التفاصيل. الحركات بعد as_of أو من مصدر/عملة/فواتير خارج النطاق لا تُبطل المقارنة.

**تطابق المجاميع لا يثبت تطابق معرّفات كل سجل أو عدم وجود أخطاء متقابلة، ولا يثبت اكتمال كل المصادر. coverage_confirmed يبقى false، وتستمر المراجعة البشرية للمكافآت.** مصدر الحقيقة لكل نوع، ومطابقة الهويات بين البرامج، وتأكيد تغطية جميع مصادر الشركة، وإدارة تصحيح/إلغاء السجلات مراحل قادمة.

## الدفعة الثانية: مطابقة السجلات

من «تحليل الأداء» اضغط «مطابقة السجلات». نزّل القالب، وهيّئ تقريراً مستقلاً من البرنامج المصدر. اختر رمز المصدر نفسه المستخدم عند استيراد الفواتير، والعملة وفترة الفواتير وتاريخ القياس، وأدخل مرجع التقرير وملاحظة المراجعة والإقرار، ثم ارفع الملف. المقارنة تحفظ أدلة مشفرة فقط؛ لا تستورد فواتير جديدة ولا تصحح أو تلغي سجلات موجودة.

CSV UTF-8 أو XLSX بقيم ثابتة، حتى 1000 سجل إجمالاً و1MiB. الواجهة تقرأ الورقة الأولى؛ API يسمح sheet من 0 إلى 9. الأعمدة ثابتة وبالترتيب:

```csv
kind,external_id,invoice_external_id,record_date,due_date,customer_number,employee_number,currency,amount
invoices,0001,,2026-10-01,2026-11-01,C1,E1,USD,10.25
receipts,R1,0001,2026-10-06,,,,USD,5.00
returns,T1,0001,2026-10-03,,,,USD,1.00
```

- kind: invoices أوreceipts أوreturns. تاريخ record_date هو تاريخ الفاتورة أو التحصيل أو المرتجع حسب النوع.
- الفاتورة: external_id وتاريخها واستحقاقها ورقم العميل والموظف والعملة والمبلغ مطلوبة؛ invoice_external_id فارغ.
- الحركة: external_id ومعرّف فاتورتها والتاريخ والعملة والمبلغ مطلوبة؛ الاستحقاق والعميل والموظف فارغة. يجب أن تظهر فاتورتها في الملف وأن لا يسبق تاريخ الحركة تاريخ الفاتورة أو يتجاوز as_of.
- كل الفواتير ضمن from/to وعملة النطاق. يلزم وجود فاتورة واحدة على الأقل. المبالغ غير سالبة، USD بدقة 2 وIQD بدقة 3، بحد المبلغ الفردي الحالي 1000000000000 وحدة صغرى. التقرير المختلط أو خارج النطاق أو ذو معرّفات مكررة داخل النوع يُرفض بالكامل.
- المعرفات نصوص حرفية وحساسة لحالة الأحرف؛ حافظ على أصفار البداية في Excel. يطابق النظام النوع والمعرّف والمصدر داخل الشركة؛ لا يدمج هويات مختلفة بين البرامج آلياً.

النتيجة تميز: متطابق / مفقود في Teami / زائد في Teami / حقول مختلفة. تُقارن المبالغ والتاريخ والاستحقاق والعميل والموظف والفاتورة المرتبطة والعملة، حسب النوع. يمكن أن تتطابق المجاميع وتختلف السجلات؛ نتيجة record_matching تعتمد السجلات نفسها.

يُفحص النطاق الطبيعي، وتُفحص أيضاً معرّفات التقرير حتى لو صار السجل المستورد خارج فترة الفواتير أو تغيرت عملته أو فاتورته المرتبطة؛ بذلك يظهر اختلاف الحقول بدلاً من إخفائه كمفقود. الحد المستورد لهذا الفحص 10000 فاتورة و10000 حركة لكل نوع. مجاميع الجدول المالي تبقى للنطاق الطبيعي فقط، ولا تجمع العملات المختلفة. الفروقات التفصيلية المحفوظة مرقمة 50 سجلاً مع تصفية النوع/الفارق، وتعرض المصدر والمستورد لكل حقل.

تُحفظ السجلات المعيارية للتقرير والمستورد والفروقات وبصمة SHA-256 للملف داخل snapshot المشفر. الملف الأصلي لا يُحتفظ به، والبصمة ليست توقيعاً من البرنامج المصدر. التفاصيل لا تعيد كل السجلات في حمولة واحدة. تغير السجلات الداخلة في الفحص أو رموز العملاء/الموظفين يظهر stale عند فتح المقارنة؛ تبقى النتيجة والفروقات القديمة كما كانت. للمراجعة الحالية أنشئ مقارنة جديدة. Idempotency-Key يمنع تكرار التقرير لنفس الطلب والملف عند إعادة الإرسال، ويُرفض استخدام المفتاح مع ملف مختلف.

تطابق التقرير المرفوع لا يثبت أنه يشمل جميع معاملات البرنامج أو جميع مصادر الشركة؛ coverage_confirmed يبقى false ولا يتغير سير المكافآت. لا تشمل الدفعة مصدر الحقيقة بين الأنظمة أو ربط الهويات المختلفة أو التصحيح والإلغاء أو الموصلات الأصلية أو المخزون والسكان والتوقعات.

## جاهزية التفاصيل

في التفاصيل تظهر أعداد الفواتير التي تفتقد منطقة محفوظة أو سطوراً أو التي لا تطابق سطورها مبلغها. يعرض القسم التالي المنتجات والمناطق ومواقع العملاء والسطور بصفحات 50 سجلاً، مع بحث القوائم الحالية. المؤشرات ضمن نطاق المصالحة فقط، ولا تمثل درجة دقة التوقعات.

لم تضف الدفعة السكان أو المخزون والانقطاعات أو تكاليف المنتجات أو مرتجعات الكميات أو نماذج التوقع؛ هذه المدخلات لازمة للمرحلة التالية. لا تستنتج نفاد المخزون من انخفاض المبيعات، ولا تنسب انخفاضها إلى المندوب دون أدلة.

## API

جميع المسارات تحت /api، بمصادقة وشركة فعالة وصلاحيات القراءة أعلاه:

| Method | Path | الاستخدام |
|---|---|---|
| GET | advisor/data/catalog?kind=products&page=1 | الأنواع products/areas/customer_locations/invoice_lines، صفحات 50 |
| GET | advisor/data/sources | رموز مصادر الفواتير الموجودة بالشركة |
| GET | advisor/data/reconciliations?page=1 | سجل المقارنات، صفحات 20 |
| GET | advisor/data/reconciliations/{uuid} | المقارنة المحفوظة وحالة البصمة وجاهزية البيانات الحالية |
| POST | advisor/data/reconciliations/detailed | multipart: نطاق المقارنة ومرجعها وملاحظتها والإقرار وfile وsheet اختياري؛ نفس صلاحية المراجعة ومنع التكرار وحد رفع imports |
| GET | advisor/data/reconciliations/{uuid}/differences?page=1 | فروقات record_matching المحفوظة؛ kind/type اختياريان، صفحات 50 |
| POST | advisor/data/reconciliations | إنشاء مقارنة؛ Idempotency-Key وصلاحية advisor.data.review |

حمولة الإنشاء: source_system, from, to, as_of, currency, invoice_count, invoice_amount, receipt_count, receipt_amount, return_count, return_amount, evidence_reference, review_note, acknowledge:true. المبالغ نص عشري دون فواصل، والدقة USD=2 أوIQD=3. ملاحظة المراجعة 12–1000 حرف ومرجع التقرير 3–255 حرف. الأعداد حتى 50000؛ الحد الفعلي للسجلات المستوردة في الفحص موضح أعلاه.

الاستجابة: status=matched/mismatched عند الحفظ؛ current_status يضيف stale عند تغيّر سجلات النطاق. snapshot يحتفظ expected/actual/differences/readiness/scope، وcurrent يعرض actual/readiness الحالية. القيم النقدية في API نصوص بالوحدات الصغرى لحماية الدقة. لا توجد عملية صرف أو تغيير رواتب أو اعتماد مالي تلقائي.

method في السجل: control_totals للمقارنات السابقة أو record_matching للتفصيلية. snapshot التفصيلي يضيف totals_status وrecord_counts وfile_sha256؛ الفروقات التفصيلية عبر المسار المرّقم، وbasis=saved_comparison. قيم حقول amount_minor وحدات صغرى بحسب عملة كل جانب.
