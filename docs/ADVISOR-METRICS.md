# مؤشرات المبيعات والتحصيل — بداية المرحلة 2

من قائمة الحساب اختر **تحليل الأداء**. يتطلب advisor.sales.read وdata.sensitive.read؛ صلاحية الاستيراد وحدها لا تمنح قراءة التحليل. أدخل فترة الفواتير وتاريخ القياس، واعرض الدولار والدينار كصفوف مستقلة أو اختر عملة واحدة. يمكنك فتح الفواتير الداعمة لكل مندوب. هذه أرقام حتمية من البيانات المستوردة، وليست توصيات نموذج AI أو قرارات مكافآت.

## تعريف الحساب

- مجموعة الفواتير: invoice_date بين from وto شمولاً.
- التحصيل: جميع إيصالات تلك الفواتير مع receipt_date <= as_of، حتى لو جاء الإيصال بعد to. ليست قيمة جميع تحصيلات الشركة داخل الفترة.
- المبيعات: مجموع net_amount_minor المستورد؛ لا نعيد احتساب الضريبة أو الخصومات ولا نطرح مرتجعات لم تُستورد.
- المرتجعات: مجموع مرتجعات تلك الفواتير مع return_date <= as_of. صافي المبيعات = المبيعات المستوردة قبل المرتجعات ناقص المرتجعات المسجلة.
- الرصيد بحسب الملفات: مجموع max(صافي الفاتورة − تحصيلاتها، 0)، دون مقاصة رصيد دائن لفاتورة مع دين فاتورة أخرى. الرصيد الدائن = مجموع max(التحصيل − صافي الفاتورة، 0)، ويظهر منفصلاً.
- المتأخر بحسب الملفات: الرصيد الموجب لفاتورة due_date < as_of. الاستحقاق في نفس اليوم لا يعتبر متأخراً.
- نسبة التحصيل: مجموع التحصيل ÷ مجموع صافي الفواتير ×100، بأرقام عشرية مقطوعة إلى منزلتين؛ تكون null دون صافي موجب، وقد تتجاوز 100% عند وجود رصيد دائن. التقرير نفسه لا يعتمد مكافأة.
- البيانات مفصولة حسب employee_id وcurrency؛ لا سعر صرف ضمن التقرير. عرض الاسم يستخدم بيانات الموظف الحالية، حتى إن كان محذوفاً حذفاً منطقياً، وليس اسم تاريخي مثبت وقت الفاتورة.

مثال اختبار: فواتير سبتمبر بقيمة 100 دولار، تحصيل 20 في سبتمبر و30 في 2 أكتوبر. عند as_of=5 أكتوبر النتيجة 50 دولاراً و50%؛ إيصال مؤرخ 6 أكتوبر لا يدخل. الفواتير خارج سبتمبر لا تدخل حتى لو حصلناها خلال سبتمبر.

API يعيد القيم المالية كـ**سلاسل بوحدات العملة الصغرى**، والواجهة تعرضها بـBigInt دون تحويل مجموع كبير إلى float. USD يستخدم 100 وحدة لكل دولار وIQD يستخدم 1000 وحدة لكل دينار. bcmath يحسب النسبة. التاريخ الحالي مأخوذ من المنطقة الزمنية للشركة ويمنع as_of المستقبل.

## اكتمال البيانات ومصدر الرقم

كل تقرير يظهر عدد الفواتير والتحصيلات وآخر استيراد مالي، مع coverage_confirmed=false. غياب إيصال في الملفات لا يثبت عدم الدفع في البنك. الفترة لا تدل أن كل فواتير المصدر قد وصلت. لا تُستنتج أرباح أو مكافآت أو أداء ضعيف من هذا التقرير وحده، لأن اكتمال المصدر والافتتاحيات والإشعارات العامة لم يُؤكد. المرتجعات والأهداف أصبحت مدعومة؛ دورة مراجعة المكافآت منفصلة في ADVISOR-BONUS.md.

الفواتير الداعمة تعرض معرّف المصدر ورمزه والتواريخ والقيمة والتحصيل والرصيد. يتيح ذلك مطابقة الرقم مع الملف الأصلي. as_of هو حد لتاريخ المستند، لا استرجاع لنسخة النظام كما كانت في الماضي؛ الاستيراد الذي جرى اليوم قد يُضيف سجلاً بتاريخ قديم إلى إعادة الحساب. هذا المسار اللحظي لا يحفظ لقطة؛ التقارير المحفوظة والمجدولة متاحة في ADVISOR-REPORTS.md.

## API وحدوده

- GET /api/advisor/sales/metrics?from=YYYY-MM-DD&to=YYYY-MM-DD&as_of=YYYY-MM-DD
- GET /api/advisor/sales/invoices بنفس المرشحات مع page لصفحات 50 فاتورة.
- currency اختياري (USD/IQD)، وemployee_uuid اختياري؛ UUID لشركة أخرى يعيد 404.
- يلزم from <= to <= as_of <= يوم الشركة الحالي. الحد 367 يوماً شمولاً و10000 فاتورة؛ ضيّق المرشح عند تجاوز الحد.
- التقرير يقفل صف الشركة أثناء جمع الفواتير والتحصيلات لحماية التناسق مع الاستيراد؛ لذلك هو تقرير محدود الحجم. توسعة الحمل والتقارير الطويلة تتطلب معالجة في الخلفية ولقطات محفوظة لاحقاً.

## الأهداف

يربط التقرير هدفاً إذا طابق الفترة والموظف والعملة بالضبط. target_minor وtarget_uuid وachievement_percent تكون null عند عدم وجود هدف مطابق؛ لا تعني أن الهدف صفر. المندوب صاحب هدف مطابق يظهر بصافي صفر حتى لو لم تصل له فواتير، مع استمرار التحذير من اكتمال الملفات. sales_minor يبقى المبلغ المستورد قبل المرتجعات للتوافق، وأُضيف returns_minor وnet_sales_minor وcredit_minor. حدود الحجم 10000 فاتورة و10000 هدف مطابق.

## التالي

تأكيد تغطية المصدر وصحة الفترة، والإشعارات العامة والافتتاحيات والحضور، ثم التفسير من نموذج AI والتقارير الدورية والسياسات متعددة المراحل.
