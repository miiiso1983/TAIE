# ملكية المنصة وإدارة المستأجرين

مالك الشركة يدير مستخدمي وبيانات شركته فقط. مالك المنصة يملك واجهة مستقلة تعرض الشركات المسجلة وتتيح إنشاء شركة جديدة وحساب مالكها. الصلاحية العامة تُمنح من الخادم صراحة عبر `php artisan teami:platform:owner EMAIL`، ولا يستطيع عضو أو مالك شركة منحها لنفسه أو عبر تعديل صلاحيات أعضاء الشركة.

السجل المستقل platform_owners يحدد هذه الصلاحية؛ لا يعتمد على localStorage أو صلاحية مفوّضة داخل شركة. تتطلب مسارات /api/platform/tenants حسابًا نشطًا ومسجلًا بهذا السجل. إنشاء الشركة لا يضيف مالك المنصة إلى عضويتها ولا يمنحه الاطلاع على موارد HR أو العملاء فيها، ولا يمنح مالك الشركة الجديد أي صلاحية platform.*. تعرض القائمة الاسم والرمز ومعرّف الدخول وحالة الشركة وعدد المستخدمين فقط.

الإنشاء يطلب اسم الشركة ورمزًا فريدًا واسم مالكها وبريده وكلمة مرور مؤكدة وقوية. تُحفظ كلمة المرور مجزأة ولا تظهر في الرد أو سجل التدقيق. الطلب يحتاج Idempotency-Key من نوع UUID، ويربط المفتاح بالحساب وببصمة HMAC للمحتوى؛ الطلب المكرر يرجع الشركة نفسها، وتغيير المحتوى بنفس المفتاح يرفض بـ409. قفل سجل مالك المنصة يمنع تكرار الإنشاء المتزامن من الحساب نفسه، وتبقى قيود uniqueness في القاعدة مانعة لتكرار البريد أو الرمز.

يتحقق التطبيق من /api/platform/context بعد الدخول، ويوجّه مالك المنصة لهذه الواجهة مهما كانت صفحة الشركة السابقة. المستخدم العادي يبقى في واجهة شركته. يبقى الدخول الحالي باستخدام حساب المستخدم ومعرّف/رمز شركته الأصلية، مع التحقق من MFA عند تفعيله. هذا التحديث لا يضيف انتحال حساب مستأجر أو تعليق/حذف شركة أو دورة اشتراكات عامة؛ إدارة الفوترة القائمة لا تزال ذات نطاق شركة.

إنشاء الشركة لا ينشئ اشتراكًا مدفوعًا أو يرسل بريدًا تلقائيًا. سلّم معرف الشركة والبريد وكلمة المرور عبر وسيلة آمنة، وهيّئ الاشتراك وفق نظام الفوترة الحالي. بيانات الشركات والأسرار الحالية محفوظة؛ migration تضيف جدولين فقط.

اختبارات الإصدار: 164 اختبارًا / 1703 تأكيدات محلية، تشمل منع التصعيد والعزل والتكرار والرفض عند تعطيل الحساب أو إزالة منحه. يضاف سيناريو متصفح لإنشاء شركة من لوحة المنصة؛ نتيجة MySQL/SQLite والمتصفح تُتحقق في GitHub CI قبل التسليم.
