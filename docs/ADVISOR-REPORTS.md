# تقارير المستشار والتفسير — الدورة الأولى

من قائمة الحساب افتح **تقارير المستشار**. يمكن توليد تقرير مبيعات وتحصيل أو ملخص HR، وحفظ نسخ ثابتة وعرض أدلتها. يمكن إعداد توليد يومي أو أسبوعي أو شهري داخل التطبيق. التفسير من AI إجراء يدوي منفصل؛ لا يُستدعى مزود AI من المجدول، ولا توجد رسائل بريد أو إشعارات خارجية تلقائية.

## الصلاحيات

كل المسارات تحتاج advisor.report.read وdata.sensitive.read. تقرير المبيعات يحتاج أيضاً advisor.sales.read. تقرير HR يحتاج hr.employee.read وhr.leave.read وhr.attendance.read. تُعاد مراجعة صلاحيات النوع عند فتح التقرير، ويخفي سجل القائمة الأنواع التي لا يملك الحساب صلاحياتها.

التوليد يحتاج advisor.report.generate؛ إعداد وإيقاف الجدول يحتاج advisor.report.manage، وإعداده يحتاج generate أيضاً. التفسير يحتاج advisor.report.explain وai.ask. صاحب الجدول هو الحساب الذي أعده، وتُراجع حالة حسابه وعضويته وصلاحياته كل مرة. سحبها أو انتهاء الاشتراك يوقف الجدول بسبب موثق في metadata؛ أعد إعداده بعد إصلاح السبب. الجداول متوقفة افتراضياً حتى ينشئها مدير مخوّل.

## النسخ والحسابات

الحقول: kind=sales/hr وfrom وto وas_of. فترة قصوى 367 يوماً، from <= to <= as_of <= يوم الشركة. التقرير ثابت بعد حفظه ويذكر وقت التوليد وإصداره. إعادة طلب نفس الفترة تعرض النسخة المحفوظة؛ new_version=true يحسب نسخة جديدة إن تغيرت البصمة دون حذف القديمة. تكرار نفس الحساب لا يضيف نسخة أخرى. as_of حد لتاريخ الحركة وليس إعادة بناء قاعدة البيانات كما كانت في الماضي.

المبيعات تتبع ADVISOR-METRICS.md: فواتير الفترة، المرتجعات والتحصيلات حتى as_of، كل عملة مستقلة، أرصدة مدينة ودائنة منفصلة. التقرير يحفظ الفواتير الداعمة والمؤشرات لكل مندوب وإجماليات العملة. المقارنة مع فترة سابقة مساوية بعدد الأيام (مثلاً سبتمبر مقابل 2–31 أغسطس)، وليست دائماً الشهر التقويمي السابق. تحصيل السابقة ينتهي في نهاية فترتها؛ قد تكون نافذة الحالية أطول إذا امتد as_of، لذا لا ندعي مقارنة عادلة تلقائياً أو نحكم على أداء موظف منها.

HR يعرض أعداد الموظفين حسب **حالتهم الحالية وقت التوليد**، وعدد سجلات الحضور في الفترة والموظفين الذين لهم سجلات والخروج غير المسجل، وحالات طلبات الإجازة الحالية التي تتقاطع مع الفترة. لا يعرض راتباً أو ملفاً طبياً أو حالات علاقات الموظفين. لا يعيد بناء أعداد الموظفين أو حالات الموافقات التاريخية عند as_of، ولا يحسب غياباً أو خصومات دون جدول عمل متوقع. هذه الحدود مثبتة داخل التقرير.

## الجدولة والتشغيل

frequency=daily/weekly/monthly وlocal_hour بين 0 و23 بتوقيت الشركة. اليومي لليوم السابق؛ الأسبوعي يولد يوم الاثنين عن الاثنين–الأحد الماضي؛ الشهري في أول الشهر عن الشهر الماضي. الموعد المحفوظ next_run_at بتوقيت UTC، والواجهة تسميه صراحة. البداية من الموعد القادم؛ لا يولّد إنشاء الجدول تقريراً فورياً.

يلزم cron لـschedule:run كل دقيقة وعامل يستهلك **analytics**. مثال محلي:

```sh
php artisan queue:work --queue=critical,ai,analytics,default
php artisan schedule:work
```

قالب Supervisor المرفق يتضمن analytics. موزع الجدولة يلتقط حتى 100 جدول مستحق في الدقيقة للشركات النشطة، مع قفل تداخل وجدولة فريدة وقفل الشركة/السجل عند التوليد. عدة مهام لنفس الموعد لا تنشئ تقارير مكررة. عند الانقطاع يولّد آخر فترة مكتملة فقط، دون استرجاع كل الفترات المفقودة. فشل المهمة النهائي بعد المحاولات يوقف جدولها بـgeneration_failed؛ لا يُخزن نص استثناء قد يحتوي بيانات حساسة. MySQL/Redis والتزامن متعدد العمال تحتاج اختبار staging فعلي.

المحتوى المالي/HR محفوظ مشفراً بـAPP_KEY؛ البيانات الوصفية فقط تبقى قابلة للفهرسة. التدقيق وأحداث outbox تثبت التوليد دون نسخ كامل البيانات الحساسة. مهمة انتهاء معاينات الاستيراد تعمل كل ساعة وتمسح المحتوى المنتهي. احتفظ بمفاتيح التشفير السابقة عند الترقية.

## تفسير AI

يُرسل السؤال كما كتبه المستخدم، ومؤشرات التقرير المجمعة فقط: الفترة، إجماليات العملات والمقارنة وحدود التغطية، أو مجاميع HR. لا تُرسل أسماء موظفين/عملاء أو أرقام فواتير أو رواتب من بيانات التقرير. قد يحتوي سؤال المستخدم نفسه على معلومات؛ الواجهة توضح أنه يُرسل كاملاً إلى مزود AI المهيأ.

الأرقام تُحسب بالكود وتظهر كقيم مراجع أصلية؛ النموذج يكتب تفسيراً نوعياً ويربط كل ملاحظة بمرجع مثل F2. يرفض الخادم مرجعاً غير موجود أو أرقاماً مولدة داخل نص التفسير أو JSON غير مطابق، ولا يحفظ تفسيراً في هذه الحالة. السؤال ليس إذناً لتعديل السياسة أو منح صلاحية. لا توجد أدوات تنفيذ أو موافقات أو دفع داخل هذا المسار. قبول بنية التفسير ومراجعه **لا يثبت صحة كل استنتاج لغوي**؛ قد يخطئ النموذج ويحتاج مراجعة مدير.

التفسير والسؤال مشفران، وسجل التفسيرات خاص بالحساب الذي طلبها. يحتاج إعداد AI_API_ENDPOINT وAI_API_KEY وAI_CHAT_MODEL في البيئة. لا يوجد مفتاح حقيقي في الحزمة. الفشل غير المهيأ يرجع 503، ورفض المزود/صيغة غير صالحة يرجع 502 دون كشف استجابة المزود. طلب التفسير يدخل حد AI الشهري عند BILLING_ENFORCE؛ إعادة المحاولة بنفس Idempotency-Key لا تعيد الاتصال أو تحسب طلباً ثانياً، والفشل يعيد الحصة وفق middleware الحالية. لم يُختبر اتصال حي بمزود AI أثناء التطوير؛ الاختبارات تستخدم مزوداً بديلاً وHTTP مزيفاً.

## API

| المسار تحت /api/advisor | الوظيفة |
|---|---|
| GET /reports?page=1 | 20 ملخص تقرير حسب صلاحيات نوعه |
| POST /reports | kind, from, to, as_of، وnew_version اختياري |
| GET /reports/{uuid} | لقطة التقرير المشفرة بعد فكها للمستخدم المخوّل |
| GET /report-schedules | الجداول المحلية للمخول بإدارتها |
| POST /report-schedules | kind, frequency, local_hour؛ يعيد تفعيل جدول متوقف مع الحساب الحالي كمسؤول |
| POST /report-schedules/{uuid}/disable | إيقاف التوليد المستقبلي دون حذف التقارير |
| POST /reports/{uuid}/explain | question حتى 2000 محرف؛ يدعم Idempotency-Key وحصة AI |
| GET /reports/{uuid}/explanations | آخر 10 تفسيرات للحساب الحالي، مع ترقيم صفحات |

## حدود دورة المنتج

اكتملت دورة أولى: رفع بيانات → حسابات وأدلة → مراجعة سياسة مكافأة → قرار مستقل → تقارير محفوظة ومجدولة → تفسير نوعي من AI عند إعداد المزود. لم تكتمل تغطية المصدر والمصالحة والافتتاحيات والإشعارات العامة ورد الأموال، ولا محرك سياسات HR متعدد المراحل أو الموصلات المباشرة والاستيراد الكبير. الإطلاق التجاري يحتاج عينة شركة مقبولة ومزود AI حي واختبارات تشغيل MySQL/Redis ونسخ واستعادة واستضافة فعلية؛ لا تُعلن الحزمة وحدها إطلاقاً ناجحاً.
